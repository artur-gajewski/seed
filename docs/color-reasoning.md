# Color question experiment

This experiment trains a byte-level Transformer to answer short questions about
explicitly stated colors and objects. Answers are one word or an object name plus
a period. It is a controlled task, not a general-purpose assistant.

## Expanded training

The expanded corpus contains 12,610 examples using six colors and 97 objects,
including submarines, berries, vehicles, animals, and multiword names. It covers
articles and missing articles, British spelling, lowercase questions, missing
punctuation, statements, instructions, object identification, and distractors.
Half the examples include a preceding conversation turn with an accurate answer.
Turns are separated by a blank line so PyTorch learns a stop token after every
answer; complete sessions are separated by two blank lines. All sessions fit a
256-token context. The supplemental generator samples complete sessions for replay.

The separate evaluation contains 2,306 examples covering held-out color/object
pairs, six objects absent from training, and conversation continuations. Reports
separate these families so good results on familiar vocabulary cannot hide poor
results on unseen words. The studio's contiguous validation tail is separate from
this evaluation. Do not import evaluation data for training.

## Train and evaluate

Run from the repository root after [installing PyTorch](pytorch.md#install). Node 24
runs the corpus generators; `seed-torch` trains and evaluates the model. `--device auto`
selects CUDA, then MPS, then CPU; use `--device mps` to require the Apple Silicon GPU.

```sh
source .venv/bin/activate
node scripts/create-color-reasoning-01.ts
seed-torch train --device auto --corpus data/inputs/color_reasoning_01.txt \
  --checkpoint data/models/color-reasoning-torch.pt \
  --embedding-width 128 --layers 3 --attention-heads 4 \
  --batch-size 8 --steps 6000 --learning-rate 0.001 --context-window 256
seed-torch evaluate --device auto --checkpoint data/models/color-reasoning-torch.pt \
  --output data/reports/color-reasoning-torch.json
```

Corpus generation and seed-42 weight initialization are deterministic. The PyTorch
CLI seeds window sampling with `--seed` (default 42); device and precision differences
can still change training trajectories. Evaluation uses greedy
sampling, exact answer matching after case and final punctuation normalization,
and up to 48 generated tokens. Conversation examples include their saved history;
other examples start a fresh chat. The JSON report records every reply and scores
by family.

To ask a single question, load the `.pt` file in Seed and use Chat. For example,
ask `What color is a yellow submarine?`. The legacy TypeScript evaluation script's
`--question` flag applies only to JSON/V8 checkpoints, not `.pt` files.

To test Chat's default sampling instead of greedy decoding:

```sh
seed-torch evaluate --device auto --checkpoint data/models/color-reasoning-torch.pt \
  --temperature 0.8 --top-k 0 \
  --output data/reports/color-reasoning-torch-sampled.json
```

The historical TypeScript expanded run had 694,146 parameters and 6,437 total updates.
Its scores below are not measurements of a new PyTorch run. It used
2,437 initial updates at peak learning rate 0.001, followed by 4,000 additional
updates at 0.0005 after removing incorrect answers from conversation examples.
For a fresh run, use the accurate corpus generated by the command above. To
continue an existing model, use the same architecture options with `--resume`,
`--steps 4000`, and `--learning-rate 0.0005`. Steps on resume are additional updates.

## Try in Seed

Stop active studio training, then choose `color-reasoning-torch.pt` in the **Models**
panel's **Select model** field and click **Load model**. Training controls prefill
from the loaded model. Open a new Chat conversation to test it; use the lowest
chat temperature for comparison with greedy evaluation.

**Continue existing model** retains learned weights. **Train with new weights** resets
weights using the selected settings. **Create new model** creates a separate named,
untrained model from scratch and selects it; it does not copy the loaded model.
Keep a backup of a trained file before resetting its weights. CLI `.pt` files load
directly, without replacing `seed_default.pt`.

Docker uses a separate checkpoint volume; a host file must be made available in that
volume to load it there. Runtime models remain in Git-ignored `data/models/`.
Reference datasets live in `data/references/`; generated score reports go in
Git-ignored `data/reports/`.

## Historical TypeScript expanded results

At 6,437 updates, greedy evaluation scored **2,256/2,306 (97.8%)** overall.
All **2,129/2,129 color questions** passed, including conversation continuations,
held-out color/object pairs, distractors, and color questions about unseen objects.
The 50 failures were object identification questions: the model still struggles to
produce object names absent from its training vocabulary.

At Chat's default sampling (`temperature=0.8`, `topK=0`), the same checkpoint
scored **2,251/2,306 (97.6%)** overall and **2,128/2,129 (99.95%)** on color
questions. The one color failure was a question without final punctuation.

The four questions from the interactive check (red car, blue berry, and yellow
submarine with and without an article) also passed **160/160** replies in repeated
four-turn conversations across temperatures 0.1 and 0.8 with unrestricted sampling.
Those are checks of known examples, separate from the held-out evaluation score.

The task still uses only red, blue, green, yellow, black, and white. These results
do not establish unrestricted color vocabulary, arbitrary question phrasing, or
general conversational ability. Sampled results can vary between runs.

## Supplemental training: add2

`data/inputs/color_reasoning_02.txt` contains 31,173 sessions (about 3.3 MB)
for continuing the existing model. It adds orange, purple, pink, brown, gray, grey,
cyan, magenta, silver, gold, turquoise, navy, violet, beige, teal, and maroon while
retaining examples of the original six colors. Gray and grey are treated as
literal spellings: answers repeat the spelling used in the question.

The supplement adds varied wording, new objects, missing punctuation, distractors,
subject switching, and follow-ups that refer to an earlier scene or an explicit
color change. Sessions range from one to five user/assistant turns. Each complete
session fits the existing 256-token context, including beginning and stop tokens.
Turns have blank-line separators so each answer receives a learned stop token.
The generator selects 4,204 earlier sessions for replay and removes duplicate
sessions before shuffling. Replay can reduce forgetting but does not guarantee it.

Both the old held-out pairs and the original six unseen objects remain excluded
from training. The separate `color_reasoning_02_reference.json` has 2,088 cases
covering new held-out pairs, unseen wording, distractors, longer chat histories,
and color updates. New held-out pairs are also absent from the original corpus.
Neither evaluation file should be imported for training.

Regenerate deterministically:

```sh
node scripts/create-color-reasoning-02.ts
```

Preserve the original model and continue a copy. This command assumes the existing
128-wide, three-layer, four-head checkpoint with a 256-token context:

```sh
cp data/models/color-reasoning-torch.pt data/models/color-reasoning-add2.pt
seed-torch train --device auto --resume \
  --corpus data/inputs/color_reasoning_02.txt \
  --checkpoint data/models/color-reasoning-add2.pt \
  --embedding-width 128 --layers 3 --attention-heads 4 \
  --batch-size 8 --steps 4000 --learning-rate 0.0003 --context-window 256
```

The 4,000 additional steps and lower learning rate are starting settings, not a
measured optimum. Use a copy of the original `.pt` file to retain a matched baseline. Compare
the new test on the original and continued checkpoints, then check the old test
for regressions:

```sh
seed-torch evaluate --device auto --checkpoint data/models/color-reasoning-torch.pt \
  --evaluation data/references/color_reasoning_02_reference.json \
  --output data/reports/add2-before.json
seed-torch evaluate --device auto --checkpoint data/models/color-reasoning-add2.pt \
  --evaluation data/references/color_reasoning_02_reference.json \
  --output data/reports/add2-after.json
seed-torch evaluate --device auto --checkpoint data/models/color-reasoning-add2.pt \
  --output data/reports/add2-original-test.json
```

Add `--temperature 0.8 --top-k 0` and use different report filenames to test Chat's
default sampling too. The supplement still uses synthetic templates and bounded
contexts; it does not establish general conversation ability.

## Earlier experiment

The original 64-wide, two-layer model trained for 4,000 updates on 420 examples
and scored 79/84 on held-out pairs of familiar words. It answered the red-car
question correctly but failed on a yellow submarine and chat continuations.
That score did not establish reliable behavior on unfamiliar objects or ordinary
conversation. The expanded experiment tests those limitations explicitly.
